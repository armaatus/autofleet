# autofleet

A shell dispatcher opens a worktree per GitHub issue; the rules, not the agent,
decide whether the pull request merges.

**Your job ends at an open pull request.** Read this file and the brief
(`./scripts/fleet/issue-command.sh <n>`). Consult [docs/](docs/) for why a rule
is the shape it is; never read it through. [REVIEW.md](REVIEW.md) is the
reviewer's, not yours.

## Hard rules

1. **This repo is its own reference installation.** `scripts/fleet/`, `.claude/`,
   `.github/` and `evals/` are the payload a host vendors *and* the copy
   autofleet runs on; working in only one is a bug. `install.sh` lists what ships.
2. **Nothing in `scripts/fleet/` may know about one project.** Ports, commands and
   protected paths all arrive through `.autofleet/`.
3. **A guard that silently stops guarding is worse than no guard.** Every rule in
   `guard.py` and `merge_gate.py` has a `--selftest` row; one without is not
   shipped.
4. **The Orca dependency is named, not hidden, and is not the default.** A build
   is one `claude -p` in a plain `git worktree` (`runner/headless.sh`, what CI
   runs); Orca code stays behind `runner/`'s `runner_*` contract.
5. **No secrets in the tree.** `.env` is generated by `scripts/fleet/env.sh`.

## Environment

Bash and Python 3.10+, no build step. Comments say *why*.

```bash
./tests/run.sh [suite [phase]]   # the suite; a `skip` judged nothing
./evals/run.sh                   # bash -n, shellcheck, both selftests
./scripts/fleet/fleet.sh status  # ...run --auto, cost; stop.sh drains
```

## The tracker is the spec

Every issue carries **Goal / Scope / Design notes / Acceptance**, and **it is the
plan** — `/implement` opens with no planning phase. Read yours in full first.

When the work turns up something an issue did not know, **edit that issue**,
yours or another's: parallel worktrees cannot see each other, and these bodies
are their only channel. Open a new one only for a reproducible defect.
Never hand-edit `blocked`/`ready`; `unblock.yml` derives them from `Blocked by
#N` lines, and one in your own issue costs you the slot.

## Finishing

`./tests/run.sh` is green, and your change has a test that would have failed
before it; for a bug fix, commit that test first. Then push, open the pull
request with `## Plan` — what the issue asked, where you departed, which issues
you edited — plus its `Closes #N` line, and **stop**. `guard.py` refuses the merge
from here, and a PR touching `.github/`, `.claude/` or `.autofleet/` never merges
itself: a person merges that one.
